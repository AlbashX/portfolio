# MASTER PROMPT

## CINEMATIC INTERACTIVE SOFTWARE ENGINEER PORTFOLIO

### Codex IDE — Full Production Build Specification

You are the lead frontend engineer, creative developer, motion designer, interaction engineer, visual systems architect, and production deployment engineer responsible for building my personal portfolio website.

This is a **high-end interactive software-engineering portfolio**, not a template portfolio and not a basic HTML/CSS project.

The website must combine:

* premium personal branding
* cinematic portrait presentation
* advanced cursor interaction
* layered image compositing
* organic mask-based image reveal
* a completely separate dark-mode identity transformation
* polished typography
* modern motion design
* responsive engineering
* accessibility
* performance optimization
* SEO
* production deployment

The final website must feel visually ambitious while remaining professional enough for software-engineering recruiters.

---

# 1. NON-NEGOTIABLE CORE CONCEPT

The entire hero experience is based around **TWO DIFFERENT INTERACTION SYSTEMS**.

Do not combine them.

Do not treat them as the same effect.

Do not implement dark mode as merely an enlarged cursor mask.

The hero contains two aligned portrait images:

### IMAGE 1 — LIGHT IDENTITY

My normal/default portrait.

It contains:

* my original face
* glasses
* normal expression
* current clothing
* full color
* normal lighting

This is the permanent base layer of the initial hero.

### IMAGE 2 — DARK IDENTITY

My transformed alter-ego portrait.

It contains:

* no glasses
* intense/revengeful expression
* half-mask
* emerald/green irises
* dark clothing
* cinematic shadows
* dramatic lighting
* darker overall atmosphere
* original interpretation inspired by dark antihero aesthetics

The two images MUST be extremely closely aligned.

Maintain:

* identical dimensions
* identical framing
* identical crop
* identical camera angle
* identical head position
* identical face position
* identical body position
* identical scale

The images must not independently move, scale, rotate, or distort.

---

# 2. CRITICAL INTERACTION MODEL

## SYSTEM A — CURSOR / FACE REVEAL

This is an **interactive reveal**, NOT dark mode.

Initial state:

IMAGE 1 fills the entire hero.

IMAGE 2 is underneath/above as a hidden masked layer.

When the cursor moves across the hero:

IMAGE 2 is revealed ONLY around the cursor.

Everything outside the reveal remains IMAGE 1.

This means:

LIGHT PHOTO
+
small organic window
containing DARK PHOTO

The dark image is NOT globally revealed.

The page does NOT switch to dark mode.

The background does NOT globally change.

The hero typography does NOT suddenly switch to a complete dark theme.

The visitor is simply discovering the hidden identity through cursor movement.

This behavior is directly based on the supplied interactive hero reference, where the alternate image exists underneath and appears only through cursor movement using an organic animated mask.

---

# 3. CURSOR REVEAL — EXACT BEHAVIOR

When the cursor enters the hero:

begin the reveal interaction.

The reveal should follow the cursor smoothly.

The reveal MUST NOT be:

* a perfect circle
* a radial gradient spotlight
* an oval
* a rectangle
* a straight split
* a hard geometric shape

Instead use an:

## ORGANIC IRREGULAR FLUID MASK

The reveal should feel like:

* liquid
* blob-like
* asymmetric
* slightly distorted
* continuously morphing
* soft around the edges
* tactile
* premium

The supplied reference specifically calls for an irregular, liquid/blob-shaped reveal with continuously morphing edges and a feathered boundary.

Target characteristics:

* approximately 250–400px overall reveal size on desktop
* soft feathered boundary
* slight deformation
* subtle inertia
* slight cursor lag
* smooth interpolation
* stable 60fps target

The cursor movement should feel like it is dragging or uncovering the hidden image.

---

# 4. CURSOR REVEAL POSITIONING

The reveal mask follows the cursor.

However, the mask itself must remain stable relative to the two portrait images.

Do NOT move Image 1.

Do NOT move Image 2.

Do NOT transform the photographs independently.

Only the mask position and shape should change.

The supplied reference explicitly requires both images to remain aligned while only the mask moves and deforms.

Use interpolation/damping so the reveal has a slight physical feel.

Conceptually:

cursor position
↓
target mask position
↓
interpolated mask position
↓
organic deformation
↓
revealed dark portrait

---

# 5. CURSOR OVER FACE

When the organic reveal passes over my face, the visitor should clearly discover:

* the mask
* the darker expression
* the green iris
* darker styling

This should create the feeling:

"I just discovered another version of this person."

The effect must preserve the underlying image everywhere else.

Example:

LEFT SIDE:
light portrait

CENTER FACE:
organic reveal showing dark masked identity

RIGHT SIDE:
light portrait

This is essential.

Do not reveal the entire dark image simply because the cursor touched the face.

---

# 6. MOUSE LEAVE BEHAVIOR

When the cursor leaves the hero:

* hide Image 2 completely
* restore Image 1 as the only visible hero portrait
* remove the reveal mask
* return to the normal state

This behavior is specifically required by the supplied reference document.

The visitor should be able to repeatedly enter and leave the hero and rediscover the alternate identity.

---

# 7. MOBILE CURSOR REPLACEMENT

Mobile has no mouse cursor.

Therefore use touch/finger position.

On touch interaction:

* Image 1 remains the base
* Image 2 is revealed through the same organic mask
* the mask follows the finger position
* the effect remains smooth
* the images remain perfectly aligned

The supplied reference also explicitly specifies touch position as the mobile interaction mechanism.

The implementation must not depend exclusively on mouse events.

Support:

* pointer events where practical
* touch interaction
* mouse interaction

Prefer a unified pointer architecture.

---

# 8. SYSTEM B — TURN DARK MODE

This is a completely different interaction.

The top-right button is:

## TURN DARK MODE

When the user clicks/taps this button:

DO NOT show the cursor reveal.

DO NOT create a blob.

DO NOT keep the light image as the dominant base.

DO NOT make the dark identity appear only inside a small cursor region.

Instead:

## DIRECTLY REVEAL THE COMPLETE DARK HERO.

The user should immediately enter the full dark identity.

The resulting screen should show:

* complete dark portrait
* complete dark background
* visible half-mask
* emerald eyes
* dark outfit
* intense expression
* cinematic shadows
* green visual accents
* dark typography treatment
* complete alter-ego presentation

This is a full hero mode transition.

---

# 9. TURN DARK MODE — VISUAL RESULT

After clicking:

LIGHT HERO
↓
DARK HERO

The entire hero changes.

The dark state should feel deliberate and immediate.

The final dark state is NOT a cursor-reveal state.

It is a complete visual composition.

Conceptually:

┌────────────────────────────────────────────┐
│ DARK NAVIGATION                 LIGHT MODE │
│                                            │
│          SOFTWARE ENGINEER                 │
│                                            │
│              [FULL DARK                    │

│                                            │
└────────────────────────────────────────────┘

The dark background itself becomes part of the identity.

---

# 10. DARK MODE BUTTON BEHAVIOR

Initial label:

TURN DARK MODE

After activation:

RETURN TO LIGHT

Clicking RETURN TO LIGHT returns to the normal hero.

The state must be deterministic.

For example:

LIGHT
↓
TURN DARK MODE
↓
DARK LOCKED

and:

DARK LOCKED
↓
RETURN TO LIGHT
↓
LIGHT

Do not let cursor movement accidentally undo the locked dark mode.

Do not allow hover behavior to fight the dark-mode state.

---

# 11. DARK MODE OVERRIDES CURSOR REVEAL

This is very important.

When dark mode is locked:

* cursor reveal is disabled
* blob mask is disabled
* dark portrait is fully visible
* full dark composition remains visible
* mouse leaving the hero does nothing
* moving around the face does nothing to the image state

Dark mode has priority over cursor reveal.

The state hierarchy should conceptually be:

LIGHT
↓
CURSOR_REVEAL
↓
LIGHT

OR

LIGHT
↓
DARK_MODE_LOCKED

Once DARK_MODE_LOCKED is active, cursor reveal is suspended.

---

When RETURN TO LIGHT is clicked:

* restore the original light portrait
* restore normal background
* restore normal typography styling
* restore glasses
* remove full dark identity
* return to the normal light hero
* re-enable cursor reveal

After returning to light mode, moving the cursor across the hero should once again reveal Image 2 through the organic mask.

Build the hero as an explicit state machine.

### STATE 1 — LIGHT_DEFAULT

* Image 1 visible
* Image 2 hidden
* cursor mask inactive
* light background
* normal typography
* glasses visible

### STATE 2 — CURSOR_REVEAL

* Image 1 remains base

* Image 2 fully visible
* dark background visible

* green eyes visible
* cursor reveal disabled
* dark typography/UI active

### STATE 4 — TRANSITIONING

Used only while animating between states.

No race conditions between timelines.

# 51. FINAL SUCCESS CONDITIONS

The project is complete only when all of the following are true.

## HERO

The initial hero shows my normal/light identity.

## CURSOR REVEAL

Moving the cursor over the hero reveals the dark masked identity only inside an organic moving mask.

The rest of the image remains light.

There is NO global dark-mode transition during normal cursor reveal.

## FACE REVEAL

When the organic mask crosses the face, the visitor sees the masked face and emerald eyes.

## MOUSE LEAVE

The dark image disappears completely and the light identity returns.

## MOBILE

Touch position controls the organic reveal.

## DARK MODE

Clicking/tapping TURN DARK MODE immediately reveals the COMPLETE dark hero.

That means:

* full dark image
* dark background
* mask
* green eyes
* dark clothing
* intense expression
* complete dark visual composition

The cursor blob is NOT used for this state.

## DARK MODE LOCK

Once activated, moving the cursor does not restore the light image.

## RETURN TO LIGHT

Clicking the return control restores the light hero and re-enables cursor reveal.

## SCROLL

Scrolling below the hero removes the special identity effects and reveals the normal portfolio.

## PORTFOLIO

About, Skills, Projects, Resume, Contact all work.

## RESPONSIVE

The experience works on desktop, tablet, and mobile.

## ACCESSIBILITY

Keyboard navigation and reduced motion work.

## PERFORMANCE

Hero interaction remains smooth.

## PRODUCTION

The application builds successfully and can be deployed.

# Syed Albash — Software Engineer

Cinematic interactive portfolio, built in phases from the master specification.

## Current milestone

Phase 4 (design system) and Phase 5 (light hero composition).

Not yet implemented: GSAP, organic cursor reveal, dark-mode state machine, dark portrait layer, mask/eye overlays, or production deployment.

## Requirements

- Node.js 20+
- npm 10+

## Scripts

```bash
npm install

npm run build
npm run preview
```

  /* Hidden by default; opacity managed by .is-revealing state */
  opacity: 0;

  /*
   * The mask uses a radial gradient clipped to an organic blob shape
   * produced by an inline SVG <feTurbulence> filter.
   * We layer two masks:
   *   1. A feathered radial gradient (soft outer edge)

  --_x: var(--mouse-x, -9999px);

/**
 * animations.js — Phase 13
 *
 * Scroll-entrance observer.
 * Watches every .fade-up element and adds .is-visible when it crosses
 * the viewport threshold. Immediately unobserves so the animation only
 * fires once per page load (no re-trigger on scroll-back).
 *
 * Zero dependencies — no GSAP, no library overhead.
 */

export function initAnimations() {
    // IntersectionObserver is universally supported; no polyfill needed.
    const observer = new IntersectionObserver(
        (entries) => {
            entries.forEach((entry) => {
                if (!entry.isIntersecting) return;

                entry.target.classList.add('is-visible');

                // Fire once, then stop watching this element
                observer.unobserve(entry.target);
            });
        },
        {
            // Element must be 15% into the viewport before triggering
            threshold: 0.15,
        }
    );

    // Observe every element that opts into the entrance animation
    document.querySelectorAll('.fade-up').forEach((el) => observer.observe(el));
}

/**
 * hero.js — Phase 5–11 state machine
 *
 * Manages the three explicit hero states:
 *   LIGHT_DEFAULT  → initial state, cursor reveal enabled
 *   CURSOR_REVEAL  → reveal loop active (managed by reveal.js)
 *   DARK_LOCKED    → full dark identity, reveal suspended
 *
 * This module owns data-hero-state on the #hero element.
 * The dark-mode button wiring is here so all state transitions
 * remain in one place.
 */

import { suspendReveal, resumeReveal } from './reveal.js';

const STATES = {
  LIGHT_DEFAULT : 'LIGHT_DEFAULT',
  DARK_LOCKED   : 'DARK_LOCKED',
};

let heroEl   = null;
let toggleEl = null;
let currentState = STATES.LIGHT_DEFAULT;

// ─── State transitions ────────────────────────────────────────────────────────

function setState(state) {
  currentState = state;
  if (heroEl) heroEl.dataset.heroState = state;
}

function toLightDefault() {
  setState(STATES.LIGHT_DEFAULT);
  document.body.dataset.theme = 'light';

  if (toggleEl) {
    toggleEl.textContent = 'Turn dark mode';
    toggleEl.setAttribute('aria-pressed', 'false');
  }

  resumeReveal();
}

function toDarkLocked() {
  // Suspend reveal FIRST so the transition doesn't fight the mask
  suspendReveal();
  setState(STATES.DARK_LOCKED);
  document.body.dataset.theme = 'dark';

  if (toggleEl) {
    toggleEl.textContent = 'Return to light';
    toggleEl.setAttribute('aria-pressed', 'true');
  }
}

// ─── Toggle handler ───────────────────────────────────────────────────────────

function onToggleClick() {
  if (currentState === STATES.DARK_LOCKED) {
    toLightDefault();
  } else {
    toDarkLocked();
  }
}

// ─── Public API ───────────────────────────────────────────────────────────────

export function initHero() {
  heroEl   = document.getElementById('hero');
  toggleEl = document.getElementById('mode-toggle');

  if (!heroEl) {
    console.warn('[hero.js] Hero element not found.');
    return { state: STATES.LIGHT_DEFAULT };
  }

  if (toggleEl) {
    toggleEl.addEventListener('click', onToggleClick);
  }

  // Ensure the DOM reflects the initial state
  setState(STATES.LIGHT_DEFAULT);

  return {
    get state() { return currentState; },
  };
}

/**
 * reveal.js — Phase 7 & 8
 *
 * SYSTEM A: CURSOR / FACE REVEAL
 * ─────────────────────────────────────────────────────────────────────────────
 * Organic cursor/touch reveal of the dark identity portrait.
 * This is LOCAL discovery — NOT a global dark-mode switch.
 *
 * Architecture
 * ─────────────────────────────────────────────────────────────────────────────
 *  • Mouse/touch position → target coordinates
 *  • RAF loop lerps current → target (creates inertia / drag feel)
 *  • Lerped values written as CSS vars on .hero:
 *       --mouse-x   interpolated X (px, relative to hero)
 *       --mouse-y   interpolated Y (px, relative to hero)
 *       --mask-size organic diameter (px)
 *  • CSS mask-image on .reveal-layer reads these vars and renders the blob
 *  • .is-revealing class on .hero controls opacity fade in/out
 *
 * State guard
 * ─────────────────────────────────────────────────────────────────────────────
 * When data-hero-state="DARK_LOCKED" the reveal system pauses completely.
 * The dark portrait is already fully visible via CSS; we must not interfere.
 */

// ─── Constants ────────────────────────────────────────────────────────────────

const LERP_FACTOR = 0.09;  // 0–1: lower = more lag / inertia
const LERP_FACTOR_RM = 0.35;  // Faster lerp for reduced-motion preference
const MASK_SIZE_DESKTOP = 420; // px – reveal diameter on desktop/tablet
const MASK_SIZE_MOBILE = 260; // px – reveal diameter on mobile touch
const MOBILE_BREAKPOINT = 768; // px

// ─── State ────────────────────────────────────────────────────────────────────

/** Current (lerped) mask position */
let cx = -9999;
let cy = -9999;

/** Target (raw cursor/touch) position */
let tx = -9999;
let ty = -9999;

/** Whether the reveal is active (cursor/finger is inside the hero) */
let isActive = false;

/** RAF handle */
let rafId = null;

/** Cached hero element and its bounding rect */
let hero = null;
let heroRect = null;

/** Whether the user prefers reduced motion */
let prefersReducedMotion = false;

// ─── Helpers ──────────────────────────────────────────────────────────────────

function lerp(a, b, t) {
    return a + (b - a) * t;
}

function isMobile() {
    return window.innerWidth <= MOBILE_BREAKPOINT;
}

/** Clamp a value between min and max */
function clamp(value, min, max) {
    return Math.min(Math.max(value, min), max);
}

/** Refresh the hero's bounding rect (call on resize) */
function refreshRect() {
    if (hero) heroRect = hero.getBoundingClientRect();
}

/** Check whether dark mode is locked — reveal must yield */
function isDarkLocked() {
    return hero?.dataset?.heroState === 'DARK_LOCKED';
}

// ─── RAF loop ─────────────────────────────────────────────────────────────────

function tick() {
    if (!hero) return;

    const factor = prefersReducedMotion ? LERP_FACTOR_RM : LERP_FACTOR;
    const maskSize = isMobile() ? MASK_SIZE_MOBILE : MASK_SIZE_DESKTOP;

    // Lerp current toward target
    cx = lerp(cx, tx, factor);
    cy = lerp(cy, ty, factor);

    // Write CSS custom properties directly on the hero element
    hero.style.setProperty('--mouse-x', `${cx}px`);
    hero.style.setProperty('--mouse-y', `${cy}px`);
    hero.style.setProperty('--mask-size', `${maskSize}px`);

    rafId = requestAnimationFrame(tick);
}

function startLoop() {
    if (!rafId) {
        rafId = requestAnimationFrame(tick);
    }
}

function stopLoop() {
    if (rafId) {
        cancelAnimationFrame(rafId);
        rafId = null;
    }
}

// ─── Reveal control ───────────────────────────────────────────────────────────

function enterReveal() {
    if (isDarkLocked()) return;
    isActive = true;
    hero.classList.add('is-revealing');
    startLoop();
}

function leaveReveal() {
    isActive = false;
    hero.classList.remove('is-revealing');

    // Move the mask off-screen so it doesn't "peek" during the fade-out
    tx = -9999;
    ty = -9999;

    // Let the loop run one more moment then stop
    setTimeout(() => {
        if (!isActive) stopLoop();
    }, 300);
}

// ─── Event handlers ───────────────────────────────────────────────────────────

function getHeroCoords(clientX, clientY) {
    if (!heroRect) refreshRect();
    return {
        x: clamp(clientX - heroRect.left, 0, heroRect.width),
        y: clamp(clientY - heroRect.top, 0, heroRect.height),
    };
}

function onPointerEnter(e) {
    if (e.pointerType === 'touch') return; // handled by touch events
    refreshRect();
    const { x, y } = getHeroCoords(e.clientX, e.clientY);

    // Teleport current position to avoid "swooping in" from off-screen
    cx = x;
    cy = y;
    tx = x;
    ty = y;

    enterReveal();
}

function onPointerMove(e) {
    if (e.pointerType === 'touch') return;
    if (isDarkLocked()) return;
    if (!heroRect) refreshRect();
    const { x, y } = getHeroCoords(e.clientX, e.clientY);
    tx = x;
    ty = y;

    // FIX: Wake up the mask immediately if the mouse moves while inside
    if (!isActive) {
        enterReveal();
    }
}

function onPointerLeave(e) {
    if (e.pointerType === 'touch') return;
    leaveReveal();
}

function onTouchStart(e) {
    if (isDarkLocked()) return;
    refreshRect();
    const touch = e.touches[0];
    const { x, y } = getHeroCoords(touch.clientX, touch.clientY);

    // Teleport so there's no swoop on first touch
    cx = x;
    cy = y;
    tx = x;
    ty = y;

    enterReveal();
}

function onTouchMove(e) {
    if (isDarkLocked()) return;
    const touch = e.touches[0];
    const { x, y } = getHeroCoords(touch.clientX, touch.clientY);
    tx = x;
    ty = y;
}

function onTouchEnd() {
    leaveReveal();
}

// ─── Resize handler ───────────────────────────────────────────────────────────

let resizeTimer = null;
function onResize() {
    clearTimeout(resizeTimer);
    resizeTimer = setTimeout(refreshRect, 150);
}

// ─── Reduced-motion observer ──────────────────────────────────────────────────

function watchReducedMotion() {
    const mq = window.matchMedia('(prefers-reduced-motion: reduce)');
    prefersReducedMotion = mq.matches;
    mq.addEventListener('change', (e) => {
        prefersReducedMotion = e.matches;
    });
}

// ─── Public API ───────────────────────────────────────────────────────────────

/**
 * Call from main.js to wire up the reveal system.
 * hero.js must call initReveal AFTER the hero element exists in the DOM.
 */
export function initReveal() {
    hero = document.getElementById('hero');
    if (!hero) {
        console.warn('[reveal.js] Hero element not found — reveal disabled.');
        return;
    }

    watchReducedMotion();
    refreshRect();

    // Pointer events (unified mouse + stylus; touch falls through to touch events)
    hero.addEventListener('pointerenter', onPointerEnter);
    hero.addEventListener('pointermove', onPointerMove);
    hero.addEventListener('pointerleave', onPointerLeave);

    // Touch events (mobile / tablet finger)
    hero.addEventListener('touchstart', onTouchStart, { passive: true });
    hero.addEventListener('touchmove', onTouchMove, { passive: true });
    hero.addEventListener('touchend', onTouchEnd);
    hero.addEventListener('touchcancel', onTouchEnd);

    window.addEventListener('resize', onResize, { passive: true });
}

/**
 * Called by hero.js / darkMode.js when entering DARK_LOCKED state.
 * Suspends the reveal so the full dark portrait remains uninterrupted.
 */
export function suspendReveal() {
    isActive = false;
    hero?.classList.remove('is-revealing');
    stopLoop();
}

/**
 * Called by hero.js / darkMode.js when returning to LIGHT_DEFAULT state.
 * Re-enables reveal on next pointer/touch interaction automatically
 * (no manual call needed — the event listeners are still attached).
 */
export function resumeReveal() {
    // FIX: Force the mask to wake up if the cursor is already hovering over the hero
    if (hero && hero.matches(':hover')) {
        enterReveal();
    }
}

/**
 * scroll.js
 *
 * Hero-aware scroll observer.
 * The identity system (cursor reveal, RAF loop) is exclusive to the hero.
 * When the hero leaves the viewport we kill the RAF loop to save CPU.
 * When it returns we hand control back to reveal.js.
 */

import { suspendReveal, resumeReveal } from './reveal.js';

export function initScroll() {
    const hero = document.getElementById('hero');
    if (!hero) return;

    const observer = new IntersectionObserver(
        (entries) => {
            entries.forEach((entry) => {
                if (entry.isIntersecting) {
                    // Hero is back in view — re-enable reveal on next interaction
                    resumeReveal();
                } else {
                    // Hero scrolled out — kill the RAF loop, free CPU
                    suspendReveal();
                }
            });
        },
        { threshold: 0.1 }
    );

    observer.observe(hero);
}
