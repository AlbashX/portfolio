## CINEMATIC INTERACTIVE SOFTWARE ENGINEER PORTFOLIO

### Codex IDE — Full Production Build Specification

You are the lead frontend engineer, creative developer, motion designer, interaction engineer, visual systems architect, and production deployment engineer responsible for building my personal portfolio website.

This is a **high-end interactive software-engineering portfolio**, not a template portfolio and not a basic HTML/CSS project.

The website must combine:

* premium personal branding

* layered image compositing

* a completely separate dark-mode identity transformation

# 1. NON-NEGOTIABLE CORE CONCEPT

The entire hero experience is based around **TWO DIFFERENT INTERACTION SYSTEMS**.

Do not combine them.

Do not treat them as the same effect.

Do not implement dark mode as merely an enlarged cursor mask.

The hero contains two aligned portrait images:

### IMAGE 1 — LIGHT IDENTITY

My normal/default portrait.

It contains:

* my original face
* glasses
* normal expression
* current clothing
* full color
* normal lighting

This is the permanent base layer of the initial hero.

### IMAGE 2 — DARK IDENTITY

My transformed alter-ego portrait.

It contains:

* no glasses
* intense/revengeful expression
* half-mask
* emerald/green irises
* dark clothing
* cinematic shadows
* dramatic lighting
* darker overall atmosphere
* original interpretation inspired by dark antihero aesthetics

The two images MUST be extremely closely aligned.

Maintain:

* identical dimensions
* identical framing
* identical crop
* identical camera angle
* identical head position
* identical face position
* identical body position
* identical scale

The images must not independently move, scale, rotate, or distort.

# 2. CRITICAL INTERACTION MODEL

## SYSTEM A — CURSOR / FACE REVEAL

This is an **interactive reveal**, NOT dark mode.

Initial state:

IMAGE 1 fills the entire hero.

IMAGE 2 is underneath/above as a hidden masked layer.

When the cursor moves across the hero:

IMAGE 2 is revealed ONLY around the cursor.

Everything outside the reveal remains IMAGE 1.

This means:

LIGHT PHOTO
+
small organic window
containing DARK PHOTO

The dark image is NOT globally revealed.

The page does NOT switch to dark mode.

The background does NOT globally change.

The hero typography does NOT suddenly switch to a complete dark theme.

The visitor is simply discovering the hidden identity through cursor movement.

This behavior is directly based on the supplied interactive hero reference, where the alternate image exists underneath and appears only through cursor movement using an organic animated mask.

---

# 3. CURSOR REVEAL — EXACT BEHAVIOR

When the cursor enters the hero:

begin the reveal interaction.

The reveal should follow the cursor smoothly.

The reveal MUST NOT be:

* a perfect circle
* a radial gradient spotlight
* an oval
* a rectangle
* a straight split
* a hard geometric shape

Instead use an:

## ORGANIC IRREGULAR FLUID MASK

The reveal should feel like:

* liquid
* blob-like
* asymmetric
* slightly distorted
* continuously morphing
* soft around the edges
* tactile
* premium

The supplied reference specifically calls for an irregular, liquid/blob-shaped reveal with continuously morphing edges and a feathered boundary.

Target characteristics:

* approximately 250–400px overall reveal size on desktop
* soft feathered boundary
* slight deformation
* subtle inertia
* slight cursor lag
* smooth interpolation
* stable 60fps target

The cursor movement should feel like it is dragging or uncovering the hidden image.

---

# 4. CURSOR REVEAL POSITIONING

The reveal mask follows the cursor.

However, the mask itself must remain stable relative to the two portrait images.

Do NOT move Image 1.

Do NOT move Image 2.

Do NOT transform the photographs independently.

Only the mask position and shape should change.

The supplied reference explicitly requires both images to remain aligned while only the mask moves and deforms.

Use interpolation/damping so the reveal has a slight physical feel.

Conceptually:

cursor position
↓
target mask position
↓
interpolated mask position
↓
organic deformation
↓
revealed dark portrait

---

# 5. CURSOR OVER FACE

When the organic reveal passes over my face, the visitor should clearly discover:

* the mask
* the darker expression
* the green iris
* darker styling

This should create the feeling:

"I just discovered another version of this person."

The effect must preserve the underlying image everywhere else.

Example:

LEFT SIDE:
light portrait

CENTER FACE:
organic reveal showing dark masked identity

RIGHT SIDE:
light portrait

This is essential.

Do not reveal the entire dark image simply because the cursor touched the face.

---

# 6. MOUSE LEAVE BEHAVIOR

When the cursor leaves the hero:

* hide Image 2 completely
* restore Image 1 as the only visible hero portrait
* remove the reveal mask
* return to the normal state

This behavior is specifically required by the supplied reference document.

The visitor should be able to repeatedly enter and leave the hero and rediscover the alternate identity.

---

# 7. MOBILE CURSOR REPLACEMENT

Mobile has no mouse cursor.

Therefore use touch/finger position.

On touch interaction:

* Image 1 remains the base
* Image 2 is revealed through the same organic mask
* the mask follows the finger position
* the effect remains smooth
* the images remain perfectly aligned

The supplied reference also explicitly specifies touch position as the mobile interaction mechanism.

The implementation must not depend exclusively on mouse events.

Support:

* pointer events where practical
* touch interaction
* mouse interaction

Prefer a unified pointer architecture.

# 8. SYSTEM B — TURN DARK MODE

This is a completely different interaction.

The top-right button is:

## TURN DARK MODE

When the user clicks/taps this button:

DO NOT show the cursor reveal.

DO NOT create a blob.

DO NOT keep the light image as the dominant base.

DO NOT make the dark identity appear only inside a small cursor region.

Instead:

## DIRECTLY REVEAL THE COMPLETE DARK HERO.

The user should immediately enter the full dark identity.

The resulting screen should show:

* complete dark portrait
* complete dark background
* visible half-mask
* emerald eyes
* dark outfit
* intense expression
* cinematic shadows
* green visual accents
* dark typography treatment
* complete alter-ego presentation

This is a full hero mode transition.

# 10. DARK MODE BUTTON BEHAVIOR

Initial label:

TURN DARK MODE

After activation:

RETURN TO LIGHT

Clicking RETURN TO LIGHT returns to the normal hero.

The state must be deterministic.

For example:

LIGHT
↓
TURN DARK MODE
↓
DARK LOCKED

and:

DARK LOCKED
↓
RETURN TO LIGHT
↓
LIGHT

Do not let cursor movement accidentally undo the locked dark mode.

Do not allow hover behavior to fight the dark-mode state.

---

# 11. DARK MODE OVERRIDES CURSOR REVEAL

This is very important.

When dark mode is locked:

* cursor reveal is disabled
* blob mask is disabled
* dark portrait is fully visible
* full dark composition remains visible
* mouse leaving the hero does nothing
* moving around the face does nothing to the image state

Dark mode has priority over cursor reveal.

The state hierarchy should conceptually be:

LIGHT
↓
CURSOR_REVEAL
↓
LIGHT

OR

LIGHT
↓
DARK_MODE_LOCKED

Once DARK_MODE_LOCKED is active, cursor reveal is suspended.

# 12. RETURN TO LIGHT

When RETURN TO LIGHT is clicked:

* restore the original light portrait
* restore normal background
* restore normal typography styling
* restore glasses
* remove full dark identity
* return to the normal light hero
* re-enable cursor reveal

After returning to light mode, moving the cursor across the hero should once again reveal Image 2 through the organic mask.

# 13. THREE PRIMARY HERO STATES

Build the hero as an explicit state machine.

### STATE 1 — LIGHT_DEFAULT

* Image 1 visible
* Image 2 hidden
* cursor mask inactive
* light background
* normal typography
* glasses visible

### STATE 2 — CURSOR_REVEAL

* Image 1 remains base
* Image 2 visible only inside organic cursor mask
* light background remains
* dark image is locally revealed
* cursor movement controls the reveal

### STATE 3 — DARK_LOCKED

* Image 2 fully visible
* dark background visible
* complete masked identity visible
* green eyes visible
* cursor reveal disabled
* dark typography/UI active

Optional transition state:

### STATE 4 — TRANSITIONING

Used only while animating between states.

No race conditions between timelines.
